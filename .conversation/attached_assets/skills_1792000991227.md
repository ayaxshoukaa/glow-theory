# Glow Theory --- Website Build Skill

## Purpose

Create a complete, polished, responsive e-commerce website for **Glow
Theory**, an online skincare, beauty, and self-care shop designed for
teenagers and young adults.

**Brand slogan:** "Your Glow, Your Rules."

The result should feel like a premium skincare brand: elegant, fresh,
feminine, confident, easy to navigate, and functional enough to
demonstrate as a university website project. Build a working website,
not merely a static mockup.

## Brand identity and visual direction

### Brand colors

-   **Blush Pink:** `#F4C2C2`
-   **Cream:** `#FFF8F0`
-   **Mocha:** `#8B6F61`
-   **White:** `#FFFFFF`

Use **Playfair Display** for headings and **Poppins** for body text.

### Design principles

-   Create a minimal, luxury-inspired skincare storefront.
-   Use generous whitespace, elegant typography, attractive product
    photography, and consistent rounded product cards.
-   Apply subtle hover states and transitions without excessive
    animation.
-   Maintain a polished, responsive layout across mobile, tablet, and
    desktop.
-   Ensure readable text and sensible color contrast.
-   Provide graceful fallbacks when product images are missing.

## Website structure and features

### 1. Home page

Create a navigation bar containing:

-   Glow Theory logo
-   Home
-   Shop
-   Bestsellers
-   Find Your Glow
-   Contact
-   Wishlist icon
-   Shopping bag icon with a live cart count

Build a hero section with high-quality skincare product imagery, the
headline **"Discover Your Natural Glow"**, a short supporting
description, and a prominent **Shop Now** button.

Also include:

-   Featured products
-   Bestsellers
-   A self-care promotional banner
-   Customer reviews, clearly marked as sample/demo content
-   Newsletter subscription section

All navigation links and calls to action must work.

### 2. Shop page

Display consistent product cards with:

-   Product image
-   Product name
-   Short description
-   Price in Kuwaiti dinars (KWD)
-   Category label
-   Wishlist/heart button
-   Add to Cart button
-   Product quick-view interaction

Use the following sample product data:

  Product                             Price Category
  ---------------------------- ------------ -----------
  Dew Drop Hydrating Serum        8.500 KWD Skincare
  Cloud Nine Facial Cleanser      6.000 KWD Skincare
  Rosy Glow Lip Oil               3.500 KWD Lip Care
  Sunday Reset Face Mask          4.000 KWD Skincare
  Velvet Skin Body Lotion         5.500 KWD Body Care
  The Glow Essentials Set        15.000 KWD Gift Sets

Use suitable product images and keep product cards visually consistent.
Product data should be maintained in a reusable, centralized structure.

### 3. Product search, filtering, and sorting

Implement functional product discovery controls:

-   Search by product name
-   Category filters: **Skincare**, **Lip Care**, **Body Care**, and
    **Gift Sets**
-   Price filter
-   Sorting by price (ascending/descending) and product name

Search, filters, and sorting should work together rather than resetting
one another unexpectedly. Include a helpful empty state when no products
match.

### 4. Find Your Glow quiz

Create an interactive quiz that asks customers about:

-   Beauty product preferences
-   Desired product category
-   Preferred routine

Use the answers to display relevant product recommendations from the
sample catalogue. Include:

-   A **Shop This Product** button that opens the relevant product or
    adds a clear route to shop it
-   A **Restart Quiz** button
-   Clear progress or question-state feedback

Do not diagnose skin conditions or make medical claims. Frame
recommendations as general beauty and self-care preferences only.

### 5. Shopping cart and demo checkout

Implement a fully functional client-side cart. Customers must be able
to:

-   Add products to the cart
-   Increase or decrease item quantities
-   Remove items
-   View each line item and the subtotal
-   See the cart item count update immediately
-   Keep cart contents after refreshing the page using `localStorage`

Handle empty-cart states and quantity boundaries sensibly. Calculate
totals from product data rather than relying on displayed strings.

Create a demo checkout form with basic validation. Clearly label
checkout as a **demonstration only**. Do not collect, store, or process
real payment information, and do not imply that a real order has been
placed.

### 6. Wishlist

Allow customers to add and remove favourite products using a heart icon.
Persist wishlist items in `localStorage`, keep the UI state
synchronized, and provide a helpful empty-wishlist state.

### 7. Product quick view

Clicking a product should open an accessible modal containing:

-   Product image
-   Product name
-   Price
-   Description
-   Add to Cart button

Support closing the modal with a visible close control and
keyboard-friendly interaction. Keep focus and modal behavior accessible.

### 8. Contact page

Create a demonstration contact form with:

-   Name
-   Email
-   Subject
-   Message

Validate required fields and email format. On successful local
submission, display a clear confirmation message. Explicitly state that
this is a demo form and that messages are not sent to a real support
team.

### 9. Newsletter subscription

Add an email subscription field with basic validation and a confirmation
message. Clearly state that this is a demonstration: do not imply that
an email has been added to a real mailing list or that a message has
been sent.

## Technical and accessibility requirements

-   Build a complete working website, not just a static mockup.
-   Use reusable components and maintainable, clearly organized code.
-   Ensure every navigation link, button, filter, modal, form, and
    interaction works as described.
-   Make the layout responsive on mobile, tablet, and desktop.
-   Use semantic HTML and accessible labels for form controls and
    icon-only buttons.
-   Provide visible keyboard focus, keyboard-friendly interactions, and
    appropriate dialog behavior.
-   Maintain sensible color contrast and meaningful image alternative
    text.
-   Handle missing or failed product images gracefully with a fallback.
-   Use sample product data and clearly identify sample reviews.
-   Persist cart and wishlist state in `localStorage`; handle
    unavailable or invalid stored data gracefully.
-   Keep all secrets and API keys out of frontend code.
-   Avoid fake payment processing and never request real payment
    details.
-   Add subtle transitions without excessive animation; respect
    reduced-motion preferences where practical.
-   Provide useful loading, success, validation, and empty states.
-   Avoid misleading claims about real email delivery, orders, payments,
    or backend services.

## Implementation guidance

1.  Organize the app into reusable areas such as navigation, product
    cards, product grid, filters, cart, wishlist, quiz, quick-view
    modal, and forms.
2.  Keep product information in one source of truth and use stable
    product IDs for cart and wishlist operations.
3.  Use shared currency formatting for KWD and calculate prices
    accurately.
4.  Keep cart and wishlist persistence logic consistent with UI state.
5.  Make active navigation and selected filters visually clear.
6.  Ensure the mobile navigation is usable and all content fits smaller
    screens without horizontal overflow.
7.  Use realistic but clearly demonstrative content; do not invent real
    customer testimonials or claim that sample forms connect to live
    services.

## Testing checklist

Before considering the website complete, verify:

-   [ ] Navigation links route to the correct page or section.
-   [ ] Search finds products by name.
-   [ ] Every category filter works.
-   [ ] Price filtering and sorting work together with search and
    category filters.
-   [ ] Add to Cart updates the cart count and subtotal immediately.
-   [ ] Quantity increase/decrease and item removal work correctly.
-   [ ] Cart contents persist after a page refresh.
-   [ ] Wishlist add/remove works and persists after a refresh.
-   [ ] Quick view opens, displays the correct product, and closes
    correctly.
-   [ ] Quiz recommendations respond to answers; restart resets the
    quiz.
-   [ ] Contact form validates fields and displays its demo
    confirmation.
-   [ ] Newsletter validates the email and displays its demo
    confirmation.
-   [ ] Demo checkout validates inputs without collecting payment
    details.
-   [ ] Empty states and image fallbacks display correctly.
-   [ ] Keyboard navigation, focus visibility, labels, and modal
    behavior are usable.
-   [ ] Layout works at mobile, tablet, and desktop widths.
-   [ ] Browser console has no errors and interactions have been
    manually tested.

## Definition of done

The final result should look and feel like a real, premium skincare
e-commerce brand while remaining honest about its demo-only
functionality. It must be visually polished, responsive, accessible,
maintainable, and functional across all listed features.
